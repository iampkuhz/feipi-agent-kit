# {{SKILL_NAME}} 术语与命名

维护时补齐实际业务对象、输入输出及容易混淆的名称；业务执行必须知道的定义放在 `references/`。

| 名称 | 含义与边界 |
|---|---|
| Skill | `{{SKILL_NAME}}`，以 `SKILL.md` 定义的任务能力为边界 |
| 运行资源 | 执行任务所需的脚本、参考和模板，会随 Skill 安装 |
| 源码维护资料 | 本目录的维护入口、术语表及按需存在的设计说明，仅用于修改源码 |

## 命名约定

- 规约或人工/Agent 审阅能力可以使用 `rules`、`review`，并说明业务对象和判定边界。
- 确定性辅助脚本按 `fetch`、`get`、`parse`、`compare`、`validate`、`save`、`render` 等实际操作命名。
- 避免重复父目录或 Skill 已表达的前缀，以及暗示脚本会智能理解、决策的名称。
- 保留现有兼容接口；不因统一风格批量重命名。
