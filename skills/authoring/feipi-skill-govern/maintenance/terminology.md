# 治理 Skill 的术语与命名

| 术语 | 业务对象与边界 |
|---|---|
| 目标 Skill / target_skill | 本次被创建、修改或审计的源码目录；不等同于已安装的治理 Skill 目录 |
| 治理 Skill | `feipi-skill-govern`，提供治理规则、初始化和校验能力 |
| 运行资源 | Agent 执行目标任务需要的说明、参考、脚本和模板，随安装分发 |
| 源码维护资料 | `maintenance/` 中的 README、术语及按需存在的架构设计资料，只用于修改源码 |
| 规约 | Agent 或维护者要遵循的业务约束，可以用 `rules` 命名；不是脚本自动理解需求的保证 |
| 审阅 | 按明确标准检查业务对象，可用 `review` 命名；确定性字段检查应写作 `validate` 等实际操作 |
| 安装树 / 打包内容 | 递归排除维护、测试、评估与第三方依赖目录后发布的有效文件集合 |
| 临时治理产物 | 本轮审计、方案、测试输出等证据，存于仓库临时目录，不作为长期维护资料 |
| 功能交付契约 | 单个业务功能的输入、规约、实际交付、消费者及完成/失败条件；不同于整个 Skill 的泛化输入输出 |
| 正式交接记录 | 绑定本轮请求和输入的中间结果，保留具体问题、交付、证据及不足，供恢复或下游消费 |
| 技术检查 / 语义效果 / 实际链路 | 分别证明确定性事实、Agent 业务分析质量、最终用户结果的传递；三类证据不能互相冒充 |

## 名称边界

- Skill 的主名称仍遵循 `domain -> action -> object -> layer`；规约与脚本的词汇不应机械替换成同一套动作。
- 辅助脚本按 `fetch`、`get`、`parse`、`compare`、`validate`、`save`、`render` 等具体操作命名，写明实际对象。
- 父目录已表达的能力或对象不再重复堆前缀；不使用暗示智能理解、判断或决策的脚本名。
- `init_skill_internal.sh`、`quick_validate_internal.sh` 等现有接口保留，本次不为风格统一重命名。
