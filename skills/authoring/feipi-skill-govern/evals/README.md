# 治理 Skill 的效果评估

`cases.json` 保存行为判定标准；能解析该文件只说明用例格式正确。语义结论必须来自实际 Agent 执行及产物审阅。

## 可复现的报告遗漏案例

在仓库根创建独立工作区，再准备原始材料：

```bash
evaluation_root="$(mktemp -d "${TMPDIR:-/tmp}/skill-govern-eval.XXXXXX")"
python3 skills/authoring/feipi-skill-govern/evals/prepare_fixture.py "$evaluation_root"
```

向独立 Agent 提供以下请求以及当前治理 Skill 路径，允许读文件、在该临时工作区修改与执行代码。不要提供 `cases.json`、预期答案、缺陷定位或修复提示：

> 使用指定的 feipi-skill-govern 完成 request.txt 中的请求。目标源码和本轮原始材料都在给定工作区，仅在该工作区内操作，不进行外部发送或 Git 操作。自行完成修改、验证与最终报告，把给用户的答复另存为 reply.txt。

审阅者事后检查：

- 实际运行生成的报告和通知是否保留 input.json 三个问题各自的症状、影响及状态；同一 Skill 的两条问题不能因去重合并而丢失。
- 无法判断的项是否仍表达缺少凭据、不能确认；不能把所有项都写成已解决。
- Agent 是否找到首次信息丢失的环节，实际修复处理或展示逻辑及必要消费者，而不只补总入口说明。
- 是否增加从原始材料推导的失败回归，指出旧 smoke 只看名称的不足，并验证真实输出；最终答复是否如实区分验证覆盖。
- 是否保留授权边界，仅生成本地通知；工作区之外没有变化。

这验证隔离环境的真实 Agent 治理及本地输入到用户产物链路，不代表远程通知服务、生产系统或所有未来请求均已验证。记录实际命令、Agent 回答、产物与审阅理由，输出保存在临时工作区。

## 其他案例

同一准备器支持 `--case analyze-only` 和 `--case stale-handoff`，各使用一个新的空目录。前者执行前后对比文件树与内容，Agent 的答复只在会话中返回，不能要求它另存回复。后者检查旧绑定未被直接信任、当前四条输入重新进入报告，分页影响更新为五条，新增时区问题不丢失，旧记录保留为历史证据。评估者只收到各自 request.txt 和原始工作区，不提前看到这些判定标准。

其余案例按 `cases.json` 的 prompt 和原始输入分别运行：普通业务请求不治理；技术通过但语义未测时不得宣称整体成功。每次报告已运行哪些案例，未运行的不能计为通过。独立 Agent 的结果支持当前 Skill 的效果判断，不能代替对目标 Skill 实际产出的再次审阅。
