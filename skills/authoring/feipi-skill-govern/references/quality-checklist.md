# 交付质量清单

按本次实际影响核对。不适用项给出依据；未验证不能勾选为通过。阶段契约见 [governance-process.md](governance-process.md)，验证方法见 [workflow.md](workflow.md)。

## 用户目标与功能

- [ ] 已从请求确定范围、授权和预期业务结果；仅分析任务未擅自实施。
- [ ] 已读目标源码维护入口与术语表，缺失项补齐；已识别实际规约、实现和消费者。
- [ ] 每个用户问题有来源、具体症状、期望、失败案例、所属环节和处理结果，不只记录 Skill 名称。
- [ ] 各独立功能明确输入、规约、交付内容、消费者、完成与失败条件；没有为简单功能强造框架。
- [ ] 总入口编排，运行规约各有归属；维护资料只维护职责与依赖地图。
- [ ] 可恢复流程绑定当前请求与输入，正式交接包含完整结果或具体不足；过期结果未被复用。

## 工程与分发

- [ ] 命名按 domain → action → object → layer；特殊名称和迁移影响已说明，旧 action-first 结论未直接复用。
- [ ] 触发、入口、功能规约、模板、实现与必要消费者一致；普通业务任务不会误触发治理。
- [ ] 修改限定目标与必要共享文件；其他 Skill 问题按需登记，无关工作区改动已保留。
- [ ] 脚本只做确定性操作，路径、临时目录、依赖预检及 macOS/Linux 差异已检查，未隐式依赖 rg。
- [ ] 安装与打包递归排除源码维护、测试、评估和第三方依赖目录；运行内容不依赖被排除资料。
- [ ] 测试和评估各归其位，运行产物只在唯一临时目录；普通 SKILL.md 不加载开发资料。
- [ ] 本次目标结构校验使用 --require-maintenance；共享验证或分发变化已验收 registry 全集。
- [ ] 改动模板/初始化后已实际生成临时 Skill，并明确其结构自检不等于业务完成。
- [ ] 旧规则、无效引用及模板残留已按改动范围检查。

## 业务证据与最终交付

- [ ] 预期从需求及原始输入独立推导；用户纠正的问题已加入回归，未照抄缺陷输出作为预期。
- [ ] 确定性正反例已覆盖受影响逻辑，测试中途失败能够真实传递到入口退出状态。
- [ ] 涉及语义能力时已检查真实 Agent 产物与来源，未用单测、dry-run、关键词或模拟答复冒充效果评估。
- [ ] 已逐项核对“来源 → 功能结果 → 报告 → 用户通知”，具体问题、结果和未解决原因未丢失。
- [ ] 外部接口的验证与接收状态真实记录；准备通知不等于已经发送，不新增无授权外发。
- [ ] 技术、语义、链路结论分别给出通过、失败、未验证或不适用及证据；平台静态检查与实测分列。
- [ ] 失败先定位所属模块，再修复及复验真实消费者；没有只往总入口追加提示词或降低预期。
- [ ] 版本与 CHANGELOG 按同日规则同步，已检查 README 入口是否需要更新。
- [ ] 最终报告含逐问题修复、验证范围、剩余问题，声明与实际证据相符；提交推送按仓库规则核验远端状态。
