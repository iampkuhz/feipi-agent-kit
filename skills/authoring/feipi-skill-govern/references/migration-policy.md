# Skill 与工作流迁移

适用于移植 Skill、工作流及其依赖，也适用于更换宿主、工具或项目环境。先明确目标环境和必须保留的业务行为，再沿实际调用逐项确认怎么承接、凭什么验收。

## 确认来源和迁移范围

固定上游版本与来源，登记正式入口及其消费者。沿入口追到实际读取的规则与资源、执行的脚本、调用的 Skill 与外部能力。逐项记录谁调用、依赖什么输入、做什么、交出什么、失败会影响哪一步。引入上游材料时保留来源及许可。仅因同仓存放或文档提及的资源，发现实际消费者后才进入迁移范围。

用 [迁移清单模板](../templates/migration-manifest.template.json) 记录来源、调用者、目标入口、处理方式、缺失时的行为和验证证据。后续升级以已记录的上游版本为比较起点。

## 决定每项依赖怎么处理

- **复用**（`reuse`）。目标环境已有满足调用契约的能力，直接使用其稳定入口。
- **移植**（`port`）。资源或逻辑可以独立分发，且允许引入，保留行为并纳入目标的分发与维护。
- **适配**（`adapt`）。目标环境能提供所需能力，但调用方式、输入或结果格式不同。明确转换和权限，并核对失败行为。
- **受阻**（`blocked`）。必需能力、权限或证据缺失时，写明受影响步骤、继续所需前提及可独立完成的工作。

比较替代能力时，对照调用者实际依赖的行为：

| 依赖用途 | 应核对的实际行为 |
| --- | --- |
| 读取状态和恢复上下文 | 从哪里读取、谁有权访问、能恢复哪些状态、缺少历史时能走到哪一步。 |
| 派工、隔离和调度 | 谁执行、使用什么身份和工作区、怎么回传结果。需要跨会话继续时，单独验证唤醒事件、恢复和停止条件。 |
| 执行与取证 | 实际操作的对象、需要的工具和权限、返回给下一步的证据。缺少真实驱动时记录具体受阻环节。 |
| 交接与验收 | 交接记录包含任务、候选、接手角色、证据和剩余工作。验收由有权的角色或规则给出绑定候选的判定。任务状态、执行结果和验收判定分别核对。 |

## 确定资料和接口的归属

- 跨项目通用的做法和 Reference 随共享 Skill 维护。项目的领域规则、启动方式、验收标准和权限从项目已有入口按需读取。当前任务的决定、证据和运行状态由任务工作区或协作系统维护。涉及恢复时，明确谁写、谁读，以及怎样核对仍是同一候选。
- 在用到资料的步骤说明要读什么、用它判断什么，以及缺失时能继续什么。沿项目明确提供的入口找到资料，复用已有文件。跨 Skill 调用指定唯一 ID，并写清触发条件、输入、返回和缺失处理。核对实际能加载目标及调用关系无环。
- 所有读、写和执行路径按 [运行路径兼容](workflow.md#运行路径兼容) 验收。优先相对于 Skill、项目或任务目录的明确根定位。固定机器路径、IDE 或宿主私有路径、个人检出路径只在上游审计留证，禁止进入运行资源及回退逻辑。外部能力通过稳定接口或项目明确提供的入口使用。

## 验证并交付

按 [迁移技术检查](workflow.md#迁移技术检查) 校验声明、来源和包内资源，再用隔离安装副本沿正式入口跑关键路径。对照实际交付物，验证换安装位置、缺少依赖或权限时的行为，以及接手和验收是否得到所需证据。分别记录已实测、受阻和未验证的能力，并交付清单及对应证据。
