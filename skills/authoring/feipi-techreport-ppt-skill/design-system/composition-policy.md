# Composition Policy

本文件只规定语义理解、叙事和信息压缩，不定义字号、颜色、间距或坐标。

## 结论优先

1. 先写页面唯一核心结论，使管理者在标题和一句 takeaway 中理解判断。
2. 再判断读者为了相信该结论需要完成的认知任务：理解结构、过程、差异、演进、决策、风险或指标证据。
3. 与结论没有直接关系的背景移到脚注、下一页或附录。

## Layout 与主视觉

- 分层架构：需要解释边界、依赖和职责层次时使用。
- 方案对比：需要做取舍时使用；先明确比较维度和推荐结论，不展示无关全量字段。
- 多方流程：需要解释参与方、顺序、交互或路线时使用。
- 指标与证据应支撑结论，不与主视觉争夺中心。
- 若两个视觉中心同等重要，优先拆页，而不是缩小所有内容。

## 信息压缩

按以下顺序处理超载：

1. 删除重复表述和不影响判断的修饰语；
2. 合并同义 bullet，保留动作、对象和结果；
3. 用分组标题表达共性，子项只保留差异；
4. 把详细口径、来源和次要证据移到脚注或附录；
5. 切换组件 size 或 Layout；
6. 删除次要内容或拆页。

禁止用连续缩小字号解决内容超载。

## 特殊内容

- 大表：只保留影响决策的列和行；其余放附录。若仍无法阅读，改为聚焦对比、分组卡片或拆页。
- 长流程：按阶段分组，突出关键路径和异常分支；跨多个认知任务时拆页。
- 复杂架构：先展示层次和边界，再在后续页面展开内部模块；不要在同页呈现所有实现细节。
- 路线图：同时存在时间、责任方和交付物时，以时间轴为主，只保留一个辅助维度。

## 面向不熟悉背景的管理者

- 首次出现的缩写给出短解释。
- 用业务影响或决策含义解释技术细节的价值。
- 区分事实、假设、风险和建议，不把推断写成已验证结论。
- 标题表达判断，不只写主题名称。

## 用户决策边界

仅在以下情况请求确认：核心结论不明确；存在两个合理但不同的叙事方向；必须删除重要内容；必须拆页；选择会改变业务含义。视觉 token、已登记组件样式和固定布局几何不要求用户重复确认。
