# AI 文本验收

执行 AI 负责完成以下检查并修正可解决的问题。无需用户复述、评分或确认“是否读懂”，也不把常规表达检查交给主 Agent 后才算完成。检查结果可保留为简短证据，不要求展示推演过程或额外生成验收长表。

## 从成稿检查可理解性

暂不借原文补全，只依据成稿，尝试提取本次阅读任务所需的核心内容：在说什么，需要的依据或关系是什么，适用条件和未决项在哪里。按文体选择检查项；叙事文章不必提供论证，邮件不必回答业务决策，清楚的短句不必扩成完整模板。

若只有依赖起草上下文才能解释的代号、只有结论标签没有必要依据，或读完不能区分主要内容与铺垫，回到材料查找可补的信息。不得把自己已知但成稿未写出的背景当作成稿表达清楚的证据。

## 对照原文检查保真

- **材料到成稿**：核心内容、独特证据、条件、异议与必要行动都有去处；删掉的部分确属同用途重复、已被明确更正或与本次阅读任务无关。成稿自身通顺，不能证明它没有遗漏原文。
- **成稿到材料**：事实、解释和因果均有依据；核对主语、动作方向、否定、状态、时间、范围及数字对象。尤其不能把“文档随实现更新”改为“实现随文档调整”，把同时发生改成因果，或把旧检查结果写成当前输入已验收。
- **补全依据**：统计对象、术语定义只能由本次授权材料确定；不得给未注明对象的数量擅加业务名词，也不借用参考例子、其他任务或常识中的事实。上下文能唯一确定的正常省略可以展开；无法确定时保留原表达，必要时列明缺口。
- **组织与用途**：证据和限制能对应其结论；同用途的重复已合并，不同用途的概述、细节和取舍理由仍保留；篇幅和结构服务本次任务，未强补统一模板。

压缩句若存在多个合理的主语、先后或依从关系解读，不选取最顺口的一种写成事实。保留能确定的内容，将原句与尚缺的关系依据放入问题清单；正文不混入“快照未给出定义”等编辑批注。业务本身的未决状态仍在正文保留。

只审阅时，对诊断清单执行原文证据与范围核对，不生成改稿。用户要求只给正文时仍完成验收，但不追加清单或验收说明。

## 核对问题清单并处理失败

按原文锚点检查每项诊断是否成立，再按实际成稿检查修复状态：已修复项仍保留，多个位置合并记录时逐处核对。改写引入的新歧义、失真或遗漏必须先修正；不能把自己造成的问题归为材料缺口交给用户。

清单不能只剩材料缺口：回查诊断阶段记录，保留已经消除的重复、混杂或无效铺垫及其依据。单纯文体适配和可选重排不算问题，不能为了补齐清单由改动倒推诊断。

- 原文有答案、成稿没说明：补回必要信息，再复核对应结论。
- 原文没有答案：保留未决事项，在问题清单中说明具体缺失及其影响，区分已处理部分与未修复部分；完成其余检查并交付。不能要求用户先验证表达，也不能伪造答案获得“通过”。
- 原文明确要求业务验收、审批或领域事实确认：保留这个业务状态。AI 完成文本验收不代表产品测试、业务批准或外部事实已经通过。

只有实际消除的缺陷才标已修复。保留真实材料缺口的交付可以完成本次编辑任务，但不得宣称全文含义已全部澄清。需要上游补充时列出最小信息缺口，供主 Agent 接续；不以“请自行检查是否准确”代替本 skill 应完成的检查。
