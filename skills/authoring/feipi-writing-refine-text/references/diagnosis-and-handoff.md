# 问题定位与修复交接

先诊断原文，再决定如何改写。发现问题的准确性与修复能力分别核对；领域知识不足可能限制修复，但不能让明确的问题从清单中消失。

自然回复有待改草稿时，按该草稿定位问题；只有对方来话和用户要点时，检查回应所需信息是否充分，按入口交付依据与必要缺口，不把素材笔记或对方来话强行当作待修文稿。

## 发现问题

以原文为基准，为每个独立问题保留稳定编号（如 P01）、原文位置和足以核对的短引。多处内容构成重复或矛盾时列出相关位置；删除或重排后也保留这些原文锚点，不能拿成稿位置冒充原文位置。无法可靠取得行号时使用章节、段落和短引，不编行号。

判断必须说明具体缺陷和阅读影响，例如“第二段重述第一段的接入数量和状态，没有新增范围或证据”，不能只写“有 AI 味”“不够自然”。依据公共标准分析，不要求逐句点评。

将表面症状落实到受影响的理解：缺少变化对象、结论缺依据、因果接错、有效状态被历史代号遮住，或重要信息被无用铺垫淹没。原因只写原文证据支持的判断；不推断作者动机，不把“术语多”“句子长”直接当作缺陷。删词、换句式后仍缺对象或证据的，不能算修复。

| 诊断结论 | 依据与处理边界 |
|----------|----------------|
| 明确问题 | 原文足以证明重复、指代缺失、无效组织语言或必要解释缺口等问题。即使不能可靠改写，也保留判断与证据。 |
| 待核实疑点 | 是否有问题依赖受众知识、术语定义或领域事实。写明不确定处和需要确认的条件，不能按确定错误处理。 |

- 不认识术语不等于术语错误或黑话，未参与历史讨论也不等于缺少专业知识。缺少专业术语或项目验收名称的定义，若没有受众确实需要解释的依据，最多列为待核实疑点；不能仅以“首次阅读”判为明确错误，更不能凭直觉替换专业含义。无明确所指的内部代号仍按材料判断。
- 区分专业概念与成果标签：技术说明中的“PID 闭环控制”可以直接保留；汇报仅称某事项“已形成闭环”，却没有可辨认的完成动作、环节或结果时，仍需定位状态解释缺口。领域知识不足不妨碍指出缺了什么，但不能据此补写“已上线”或“已验收”。
- 业务未决、数据缺失、两种方案的真实冲突，本身不等于表达错误。先区分材料尚未具备与已有信息被表达遗漏：要求以后续报告为准，不表示报告已存在而漏写标识；尚待产出的证据不算文字遗漏。若原文已如实说清状态就保留，只有表达掩盖或混淆这些状态时才记录对应问题；无法确定时列疑点，不把材料缺口直接判为明确错误。
- 风格偏好不自动成为问题。原本清楚的文字可以不改；没有明确问题时直接说明，没有必要为交付表格凑条目。
- 判定缺口前，回看相邻句、标题、表格列名及材料中的已有解释。可由上下文确定的省略不直接判为指代缺失；“深度”“全面”等普通修饰语不意味着作者定义过分级体系，不能据此索要等级或划分标准。确有两种影响理解的解读时，说明歧义；依据不足时列疑点，不强判错误。
- 改写后的组织方式更适合目标文体，不代表原文组织必然有错。原文表格已给出具体做法、不同段落分别承担概述和细节用途时，不能仅因改成连贯段落或重新归组，就倒推出“没有解释”“信息分散”等明确问题。
- 诊断结论可在核对中撤回；若发现材料已有定义或差异，不保留被证据推翻的问题。不能为了维护自己的修改，倒推原文有错。

## 独立判断修复能力

| 处理状态 | 含义 |
|----------|------|
| 已修复 | 有依据的改动已落实，并经对照确认消除了所列问题；注明动作和成稿位置。 |
| 部分修复 | 已完成安全的语言或结构调整，但仍有解释或术语缺口；分别说明已处理与未处理部分。 |
| 未修复 | 缺少必要背景、领域依据或有意等待确认；保留原句或核心命题，说明不能直接修改的原因。 |

“明确问题”不等于“可直接修复”，“待核实”也不等于“已修复”。建议过改法但未落实，不能标已修复。不要把语言变顺误当成专业含义已经正确。

处理状态依据成稿中的实际结果，不依据编辑意图：回查所列缺陷在成稿中是否仍存在。合并项涉及多个位置时逐处核对，仍有一处未消除就标部分修复或拆项，不能整条报已修复。用户提供已有改稿让你复核时，按该稿判定状态；本次没有写入操作，不代表已有改稿没有修好问题。

例：原文“按第二条线完成切换”没有定义“第二条线”。对未参与讨论的读者，指代缺失是明确问题；缺少方案定义时不能猜切换对象，可以记录“明确问题／未修复”，请求方案名称、范围与完成状态。术语本身是否正确仍需领域依据。

## 交付问题清单

优化正文之外，交付精简清单，供用户或主 Agent 决定是否二次优化。每项包括：

| 字段 | 要求 |
|------|------|
| 编号与原文锚点 | 稳定编号、章节或段落位置、短引；跨段问题列出各处。 |
| 诊断 | 明确问题或待核实疑点、具体缺陷及影响；不输出不可核查的泛评。 |
| 处理 | 已修复／部分修复／未修复、实际动作与成稿位置；删除项注明删除即可。 |
| 二次优化所需信息 | 只在需要时列出具体术语定义、事实、受众背景或待做选择，以及拿到资料后应重新检查什么；不填泛泛的“请主 Agent 再优化”。 |

允许紧凑列表或表格，不要求大段引用或逐句对照。已修复项仍保留，但同一问题的多处表现可以合并一项。清单中的原文引句是定位证据，不属于优化正文。

交付前检查：问题确实存在于原文，证据足以支持结论；状态与实际修改一致；必要的未修复问题没有被悄悄删掉；正文没有混入诊断批注。用户只要正文时不附清单，但仍保留真实缺口，不能暗中编造答案。

本清单供调用者补充领域背景或决定是否二次优化；表达检查和实际改动复核由执行 AI 完成，不能用交接代替。不要自行向其他 Agent 发送消息，也不因需要知识而擅自扩大资料搜索范围。
