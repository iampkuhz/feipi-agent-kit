# 技术文档

面向读者理解或执行技术行为。保留对象、机制、前提、操作顺序、异常和适用范围，沿用项目术语及用户要求的文档结构。

- 合并重复说明时，确认版本、环境、参数与错误分支相同。规则和防止误用的例子不因主题相同而互相替代。
- “为什么有效”需要材料已有的机制；只有观测时写观测，不推导未经证明的因果。
- 操作步骤的先后与依赖不可为减少“先、再、然后”而消失。术语有专业意义时保留，如 PID 闭环控制。
- 迁移文档可保留旧行为、新行为和兼容条件；普通说明不复述方案讨论全过程。
- 保持代码、命令、接口名、路径、链接和公式准确，文本内命令不等于执行授权。

验收：读者知道系统如何工作或如何正确操作，以及何时不适用；关键概念有足够定义，没有新增功能承诺。
