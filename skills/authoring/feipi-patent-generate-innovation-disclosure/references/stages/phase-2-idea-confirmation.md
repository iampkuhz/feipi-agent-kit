# 阶段 2：写作思路确认

> 仅供阶段 2 主 agent 加载。本阶段禁止 subagent；不加载阶段 1 guide、原始材料、正式模板或质量总表。

## 输入与边界

只读取已封存的 `phase-1/handoff.md`、其中明确点名的 `phase-1/model.md` 条目，以及用户本轮新增的确认、否决或补充。不得为“补上下文”重读既有原始材料或检索页。

若用户新增或改变来源事实，先记录回退理由并回阶段 1 更新材料索引；只有对既有候选的取舍、措辞或确认可以留在本阶段。

## 形成可确认的写作思路

主 agent 生成 `phase-2/decision.md`，至少包含：

- 一句核心发明主张与章节论证顺序。
- 候选 I/T 一一映射，以及每项创新的已实现基础、实质差异、价值因果和可观察效果。
- 每项拟扩展保护使用 `> **拟扩展保护（IEx）**` 独立高亮，并说明依据 SF；没有扩展时不放空块。
- 竞品检索的范围、日期、证据或“已检索但无可用证据”结论。
- 图示职责、候选 D/E/S 编号、条件部署图触发情况。
- 证据缺口、不能由本地脚本证明的边界和需要用户作出的具体选择。

这是内部确认材料，可以显示 `SF/IE/EM`；同时明确这些编号、定位和机器枚举不会进入对外版。只给确认所需摘要，不提前扩写最终正文、完整 manifest 或最终图包。

## 等待用户

- 明确标注“思路待确认”，以一条 `DECISION` 合并核心主张、主要边界和用户需要确认的选择。
- 运行 checkpoint `wait-user` 后结束当前对话轮次；沉默、未回复和仅补充材料都不是确认。
- 用户要求调整时更新 `decision.md` 并再次等待；如果调整改变 SF，回阶段 1。
- 等待用户不是阻塞，不轮询、不催询、不启动阶段 3。

## 冻结与封存

收到明确确认或等价表述后，冻结：

- I/T/D/E/S 集合与含义。
- 已实现基础和逐项 IE 扩展边界。
- 图示职责、图型选择和部署触发。
- 阶段 3 需要按节点读取的模板，以及仍存在但不阻止成稿的警告。

将上述决定写入 `phase-2/handoff.md`，只使用稳定 ID、路径、hash 和未决项；完成最低检查后封存 `phase_2_idea_confirmation`。阶段 3 只消费该 handoff，不接收阶段 1 原始材料。

如果用户无法确认某项是否已实现，或不同选择会改变核心主张却没有明确答案，继续保持 `waiting_user`；不能自行把拟扩展写成实现事实。
