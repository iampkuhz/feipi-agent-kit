# Brief 与 draw.io 编写

brief 是 UTF-8 JSON，仅含 `title`、`diagram_type`、`nodes`、`edges` 四个字段。JSON 使用标准库，无 YAML 依赖。

- `nodes`：1–60 个节点，必填 `id,label,x,y,width,height`；`id` 以英文字母开头，后续为字母、数字、下划线或连字符，最长 64 字符。
- `shape` 可选：`rectangle`、`rounded`（默认）、`ellipse`、`diamond`、`cylinder`、`group`。
- `parent` 可选：父分组节点的 ID；坐标相对父分组左上角。分组标题占上方 36 像素，子节点 y 至少留 44 像素，最多 4 层。
- `edges`：0–100 条，必填 `id,source,target`；`label` 可空，`points` 为可选绝对坐标数组 `[[x,y],...]`，最多 12 点。连线在根层，方向为 source → target。不支持自环，可加入显式步骤节点表达反馈。
- 坐标/尺寸需有限数字；x/y 为 0–5000，宽为 40–5000，高为 36–5000；实际渲染宽高不超过 6000 像素。

生成器支持普通文字和换行，自动做 XML 转义。不要手工把 `&` 写成 `&amp;`。每个标签最多 200 字符，文件最大 2 MiB。

先按图意排版：架构图按层/域分组，流程图保留分支语义，树图按深度与兄弟节点排布。建议普通节点宽 180–240、高 80–100；水平间距至少 120、垂直间距至少 80。复杂关系用路由点绕开其他节点。节点尺寸、位置属于 brief 合同，修图时一起更新。

已有 `.drawio`：压缩页会在内存中解压验证，原文件保留；只处理一页。多页逐页产出独立图包。导入内容含 HTML、图片、链接、自定义 stencil、隐藏/折叠 cell 或非标准 XML 元素时明确报告边界，先保留原件再整理成普通文字/矢量图形，不静默简化业务需求。支持的内置 shape 以实际本地渲染与视觉复核为准。

分组、节点和连线 ID 不复用；根层固定 `0/1`，其他 cell 必须全部出现在 brief。`diagram_type` 不限制为 UML 图型，但报告不验证时序、部署等专属业务语义。
