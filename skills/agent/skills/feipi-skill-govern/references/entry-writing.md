# 入口与迁移中文

## 已加载入口

共享 `SKILL.md` 面向已经加载它的执行者。写适用条件、当前会话责任、工程步骤和停止条件。入口自己的启动命令放到实际客户端配置或用户文档。宿主通用步骤直接说明动作；专用宿主的工具、权限和已兑现的能力可在实际使用步骤或按需 Reference 说明。保留跨 Skill 调用的准确 ID 和真实项目入口。

校验器检查正文中明确写出的本 Skill 调用命令。审阅者结合上下文识别重复自介、无谓宿主限定和真正的能力依赖。文件路径、元数据和其他 Skill 的有效调用维持既有语义。另用实际宿主或隔离消费者核对加载行为，工具名出现或缺席本身不证明宿主耦合。

例如，正文用“用户显式启用本模式后，由当前会话选路并执行”。宿主配置可给用户实际的启动提示。工程路线需要委派时，写要核对的角色、权限与回执；只有必须使用特定工具时才写工具名。检查时同时覆盖紧贴中文的自调用、其他 Skill 的准确 ID 和实际包内文件路径。

## 上游中译与候选改写

1. 先读前后段落、章节和调用关系。找清谁负责、何时做、用什么对象、动作顺序、必需约束和停点。指代或术语歧义先确认在本节的实际范围。
2. 用自然、简洁的中文表达同一行为，保留专名、代码、判据和例外。删除翻译腔造成的复述，不能顺手扩大触发、放宽验证或引入原版没有的机制。
3. 忠实中译随固定上游保留。候选里需要的角色适配、新入口、授权边界和版本差异单独说明，写明删除、移动或替换的原因和影响。
4. 成稿回查上游、忠实中译及候选。逐段核对上下文、条件、动作、约束、证据和出口，同时试读中文是否能被操作者和执行者直接使用。有关选择器、角色或真实运行面的改动另补验证。
