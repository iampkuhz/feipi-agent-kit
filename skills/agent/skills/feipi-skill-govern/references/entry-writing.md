# 入口与迁移中文

## 已加载入口

共享 `SKILL.md` 面向已经加载它的执行者。写适用条件、当前会话责任、工程步骤和停止条件。入口自己的启动命令放到实际客户端配置或用户文档。宿主通用步骤直接说明动作；专用宿主的工具、权限和已兑现的能力可在实际使用步骤或按需 Reference 说明。保留跨 Skill 调用的准确 ID 和真实项目入口。

校验器检查正文中明确写出的本 Skill 调用命令。审阅者结合上下文识别重复自介、无谓宿主限定和真正的能力依赖。文件路径、元数据和其他 Skill 的有效调用维持既有语义。另用实际宿主或隔离消费者核对加载行为，工具名出现或缺席本身不证明宿主耦合。

例如，正文用“用户显式启用本模式后，由当前会话选路并执行”。宿主配置可给用户实际的启动提示。工程路线需要委派时，写要核对的角色、权限与回执；只有必须使用特定工具时才写工具名。检查时同时覆盖紧贴中文的自调用、其他 Skill 的准确 ID 和实际包内文件路径。

## 让当前段落足以开始行动

- 先写当前角色要做的动作，再给动作直接需要的文件、可用位置或链接。新术语仅在影响这一步选择或执行时引入，首次出现一句说明它是什么、谁用它、在哪里取得。后续才消费的概念和资料放到首次实际使用的位置。
- 迁移新增角色、文件或机制前，核对上游同一段究竟要求了什么，以及目标环境谁会消费新增内容。只有能补足当前步骤所需输入、权限或行为的适配留在该步骤，说明其必要性。用目标环境中的具体动作表达，保留必需的入口、读取顺序和缺失停点。
- 复审时从文件开头按顺序读。只凭已读内容和本步直接链接，试着说出谁做什么、从哪个根读什么、何时移交。需要搜索陌生术语、跳读后续章节才能执行当前动作时，改写为就地可操作的指令，再复核依赖与落点。

## 先还原原文要求的行为

- 先说明该段在流程里解决什么。对会改变选用、执行或验收的句子，查阅上下段及原文实际指向的调用处，还原什么情况触发、哪个角色先做什么、输入由谁提供、预期结果和例外是什么。记录相应原行号和直接调用证据，再写中文。
- 用一个贴近实际的情形试读原文和候选。对容易错解的规则，再加入一个会得出不同动作的边界情形，例如某句话究竟决定要不要启动执行者，还是限制已经决定启动时的第一条指令。两种读法会导向不同动作时，先核对真正控制该动作的入口，再把判据写回解读和候选。无法从来源确认的判断标明推断或缺口。
- 迁移适配另记新旧执行者、实际输入和结果变化。原文行为已明确时保留其作用及强制程度。明确的先后、必读范围、停止条件与例外要写在实际约束动作的句子里，读者只看该处就能执行。若候选调整了时点、角色、必需条件或能力范围，在审阅稿说明原因和后果。上游或反馈前候选的段落已提供仍有效的首读材料定位时，在同一段保留可用的直接引用和解析根。区分首读材料的导航与派工动作的触发，后者的条件和其余交接资料放在正式执行处。中文和英文用词近似只证明字面相似，验收看首次阅读者能否作出同一判断或理解已声明的差异。

## 核对 Markdown 标记背后的引用

- 转写前清点加粗、行内代码、链接、标题、列表首项和表格键。把显示词相同、同名或词干相似、按标题派生等情况作为待查线索。从固定上游的目录或注册表查实际资源，再读调用规则、目标声明或消费者。记录原标记与位置、目标准确名称及路径、选择或解析规则、支持这个判断的证据。无证据时仅标推测。
- 核实标记是在提示调用、用于派生标识或检索、标出条目名称，还是只强调约束。同一拼写可能落在不同类型的资源上，要用路径、调用者和适用条件消除歧义。候选为仍有效的引用保留准确英文、ID 或锚点，并明确实际读谁。原资源未迁入时保留有用的上游定位词，写清当前替代及缺失行为。上游标识本身不构成调用或安装依据。
- 比较原结构和候选结构。并列条目反复用名称或标题查找对应规则，且每项只需一段短说明时，可用「名称｜适用条件与动作」两列表。独立章节、顺序流程、长例外和多分支规则优先保留相应层级或列表。按实际渲染核对两列是否易扫读，核对序列、例外、内联代码和调用目标是否仍然清楚。只在有具体收益的组更换结构。

## 候选的表达主线

以当前步骤中读者要作出的判断或动作决定取舍与写法。正文先给能决定该行为的信息，已在其他真实入口消费的细节留在那里。读者容易把两件事混在一起时，把会改变执行结果的条件写到实际动作前。按[候选写法与取舍](manual-review.md#候选写法与取舍)用具体场景说明这一选择。

### 按实际执行点收拢重复规则

- 同一要求的完整规则放在实际使用它的入口或 Reference。上层保留选路条件、必须在下一步前知道的约束，以及能直接找到细则的引用。已经在开工处说明的项目定位，只在后续步骤需要作出不同判断时补充。迁移中的上游来源、缺失清单和适配理由留在相应依赖说明，执行位置保留会改变当前动作的替代方式和停点。
- 判断重复时看各处承担的职责。例如，选路处交代何时需要委派，派工处规定第一条指令必须让受派者先读工作说明，执行参考记录传参、可读路径和回执。三个职责都要能独立找到。若几处只是反复解释同一份材料怎么定位，把细节收拢到实际传递路径的一处。
- 精简后保留原有的触发、角色、顺序、强制程度、授权、停点和例外。保留会影响选择的路线区别，以及实际用来解析或检索的英文名称、准确 ID、路径或锚点。原文要求若改成可选、延后或交给其他角色，按行为变化核实并记录。有效性用[查重与保真复核](workflow.md#查重与保真复核)检验。

## 上游中译与候选改写

1. 先读前后段落、章节和调用关系。找清谁负责、何时做、用什么对象、动作顺序、必需约束和停点。指代或术语歧义先确认在本节的实际范围。
2. 用自然、简洁的中文表达同一行为，保留专名、代码、判据和例外。删除翻译腔造成的复述，不能顺手扩大触发、放宽验证或引入原版没有的机制。
3. 忠实中译随固定上游保留。候选里需要的角色适配、新入口、授权边界和版本差异单独说明，写明删除、移动或替换的原因和影响。
4. 成稿回查上游、忠实中译及候选。逐段核对上下文、条件、动作、约束、证据和出口，同时试读中文是否能被操作者和执行者直接使用。有关选择器、角色或真实运行面的改动另补验证。
