# Multica 项目与任务协作

默认使用已安装的官方 `multica`。项目、Issue 和 Agent 以平台查询为准；无需安装本机运维包装器、加入受管 Agent 名单或对齐部署声明。首次使用时看本机版本和相关子命令帮助，不自行登录、升级或改部署配置。

## 确定身份与目标

- 已有明确的工作区、项目和 Issue，直接核对后操作。平台提供的当前任务及项目上下文也是有效入口，不需要重新接入仓库。
- 用户说“当前仓库的任务”，才用 `python3 "$SKILL_DIR/scripts/project.py" context --directory 实际目录` 自动定位。`SKILL_DIR` 是本次加载的 Skill 目录。机器映射与仓库入口只服务自动发现和主动关联，见 [项目接入](references/project-setup.md)。
- 后台沿用本次注入的任务身份。task token、task ID、agent ID、workspace ID 和 server URL 必须完整；不得改用个人 profile。身份不全时安全停止写入，保留本地结果。
- 每次写入都先核对工作区、项目和 Issue 的归属，复用单轮已经核实的信息。目录执行还需核对实际 cwd 与用户授权范围；已存在活动 Run 时不能未经核对重复启动。

只有用户明确要求任务写入，或仓库规则在本次客户端与工作范围内明确启用主动协作，才关联并回写。分析产生了报告或本地文件本身不构成写入 Multica 的授权。

## 按意图操作

| 意图 | 入口与结果 |
|---|---|
| 管理项目本身 | 清单、概览、建项、状态、日期、负责人、仓库资源等见 [项目管理](references/project-management.md)。项目状态和 Issue 状态分别核实。 |
| 查询、创建、更新 Issue | 优先用原生 list/get/create/update；正文用 [需求模板](templates/task.md)。完整的轻量根线程索引用于查找有效要求，再展开相关线程；不把最新五条当全历史。 |
| 当前聊天处理 | 在已有授权和项目范围内继续工作。必要的归属备注只表示“由当前聊天处理”，不表示取得目录锁或接管原生会话。 |
| 派发或交接 | 从平台 Agent 清单取得准确 UUID，核对目标和活动 Run，再用原生无启动分派与明确 mention。交接包见下文，命令见 [操作参考](references/operations.md)。 |
| 发布结果 | 用评论、已有提交/PR 或用户需要的附件发布实际结果；可参考 [交付模板](templates/delivery.md)。发布材料不自动改整单状态，也不代表验收通过。 |
| 申请验收或改状态 | 依据整单完成情况、用户意图和项目工作流选择实际状态键，再单独 update `--no-start` 并读回。部分成果不强制进入 Review。 |

原生写操作的核对顺序、评论文件与线程要求、回执和可选恢复工具见 [操作参考](references/operations.md)。用户明确授权的后续动作连续完成，不重复确认；候选歧义、身份或范围冲突才集中澄清。

## 执行端与平台契约

当前运行环境给出的回复规则优先于通用示例。后台按本轮实际 trigger/thread 目标回复；若平台要求每轮只发布最终评论，就不要另发开始、进度和交付评论。合并多线程或特殊角色的回复目标遵守平台给出的具体契约。

Agent 评论先写工作目录内的 UTF-8 正文文件，再用 `--content-file` 发送；不以 stdin、inline content 或 shell 转义拼接正文。只在发送成功后清理正文文件，失败或结果未知时保留。普通更新需要保持静默时使用 `/note`；需要唤醒下一角色才显式 mention。

派发端只核实平台可查询的身份、归属、活动运行及资源约束。必需可执行文件、MCP、实际 cwd 和验证能力由实际执行端确认；未知不等于可用，也不等于不可执行。模型、推理等级、并发与本机声明的差异属于运维诊断，不是普通任务的必经关卡。

交接包用 [模板](templates/handoff.json) 写清目标、范围、期望目录、通过标准、已有产物和剩余工作。`required_executables` 只放程序名；`validation_commands` 放完整验收命令；`required_mcp` 放执行端需核验的能力。执行端先做有界检查，有真实缺口就反馈具体失败层，不伪造可用结论或自行修改个人环境。

## 结果、重试与边界

返回核实过的项目/任务链接或 UUID、做了什么、实际状态及执行者、证据或剩余问题。queued 只是派发已接收，退出码零不等于需求通过；“已发布材料”“已申请验收”和“已验收完成”分别陈述。

原生操作结果未知时先读回评论、Run、字段和附件，不盲目重发。已有的 `multica-work` 可选用于本机操作回执，不是默认入口、全局去重或平台调度器；恢复方法见操作参考。平台本身也有同 Issue/同 Agent 的触发合并机制，本机回执只补充同身份、同请求的重试记录。

服务运维、模型部署、渠道通知和客户端私有会话接入不属于此 Skill。专用项目规则按当前项目加载，不把历史环境的角色或工具配置当作通用限制。
