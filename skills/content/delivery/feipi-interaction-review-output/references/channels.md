# 渠道与产物

依据当前执行工具、任务说明和已核实的能力选择交付方式。Agent 品牌不等于用户渠道；渠道原生支持也不等于当前连接已经接入。未知能力使用普通文本兜底。

## Codex 官方远程界面

- 正文放本轮结论、必要依据、验证限制和真正需要用户处理的事项。已有原生变更查看或文件入口时优先复用，不把整段 diff 或终端日志复制到对话。
- 本机文件路径可作为定位证据；只有当前客户端已支持并核实打开路径时，才作为查看入口。手机无法直接使用的电脑目录、应用命令和 localhost 链接不能冒充已交付产物。
- 不在正文画出假按钮，不承诺 Skill 能修改客户端 UI。客户端版本、账号和连接能力不明时，保留必要内容于正文，并明确详情入口的实际状态。

## Telegram 与其他 Chat Channel

- 先给可独立理解的摘要，附件或已核实链接承载详情。按渠道实际格式和长度限制组织；确需拆消息时按完整事项拆分，让各条能识别所属任务，不为排版反复通知。
- 只有当前发送工具支持，且接收与回调处理均已接入时，才使用动作按钮；只有链接已核实时才使用 URL 按钮。否则采用明确的文字回复方式，不把方括号文字装成可点击控件。
- 查看详情、选择方案和批准执行要分开；可执行动作绑定当前任务、版本和授权范围。原 Agent 或现有渠道处理重复、过期回复，Skill 不建立回调服务。
- 更新已有消息仅在工具支持、更新目标已核实且不会隐藏关键状态变化时使用；不能默认以更新代替用户需要看到的完成或失败通知。
- 外发内容沿用当前用户授权、接收范围和隐私约束；不因电脑产物打不开就公开托管，或把凭据、本地运行资料发到聊天。

## Multica 任务结果

- 当前任务及运行环境规定的回复线程、最终评论、附件和状态契约优先；每次汇报前审查不意味着新增开始、进度或通知评论。
- 区分执行 Run 结束、材料发布、验证通过和整单验收；展示实际证据与剩余问题，不因界面显示 completed 就写“全部完成”。
- 通过当前身份可用的原生任务或附件入口交付；本地生成附件、上传成功、绑定到目标任务和接收端可下载分别核实，不更换身份或绕过授权补交付。

## 产物选择

短结果直接放正文。较长材料提供摘要与可访问详情；图形内容可按需提供预览，但保留用户真正需要的可编辑原件或数据。选择取决于阅读与操作任务，不默认生成 HTML、PDF、截图或额外网站。
